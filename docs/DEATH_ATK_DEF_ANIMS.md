# Identifying every npc's attack, defend and death animation — and its sounds

Every npc in this tree was seeded from `[default]` in `npc_default.npc`, which
hands out the *human unarmed* set: `human_unarmedpunch`, `human_unarmedblock`,
`human_death`. That is the right global fallback — it is the one animation family
not tied to a creature's skeleton — and it is wrong for every non-human npc. A
dragon died by folding up like a man.

This is the automated method that fixes it, and the record it leaves behind.

    python3 tools/gen_npc_combat.py --validate    # measure every layer, write nothing
    python3 tools/gen_npc_combat.py --write       # write the ledger and the config

Companion to `docs/NPC_SOUNDS_ANIMS.md` (the search for a source, which concluded
no public one exists for a modern cache) and `docs/WEAPON_FX.md` §6 (the player
half of the same problem).

---

## 1. What made this tractable

Two measurements, taken before any code was written, decide the whole design.

**Every sequence in this cache carries Jagex's own name.** All 14,413 of them,
via the February 2025 leak the OSRS Wiki published (`gen_sound_names.py`'s
header). 1,277 are named `*attack*`, 758 `*death*`, 642 `*block*`/`*defend*`.

**Every npc is anchored to a rig.** 14,053 of 16,292 state a `readyanim`, which
resolves to a framemap, which is the skeleton the npc's model is built on.

Neither alone is enough. A pure name join answers about 100 npcs, because
sequence prefixes name *families* rather than individuals. A pure rig join is
ambiguous, because a rig carries every animation of every creature that shares
it. Together they are decisive: **the rig closes the candidate set and the name
classifies within it.**

A third measurement changed the sound half. **1,588 sequences carry their sound
in-band**, in the cache, as `sound=frame,id,loops,location,retain,weight` — and
the client already plays them (`app_play_frame_sounds`, `src/app.c`). So for
modern content, identifying the animation *is* identifying the sound. The
"npc sound is server data" conclusion of `NPC_SOUNDS_ANIMS.md` binds only the
2004-era rigs, whose sequences predate the in-band field.

## 2. Where the output lives, and why it is two files

**`OSRS-Content/osrs239-content/npc_combat/<shard>/<gameval>.combat`** — one file
per npc, 16,292 of them, sharded by first character. This is the *decision*.

**`server/scripts/npc/configs/npc_anims.generated.npc`** — compiled from the
ledger. This is what the game reads.

A representative ledger file:

```
// Cow
// npc 2790 - rig framemap 1338 (44 sequences)
//
// Generated by tools/gen_npc_combat.py. Re-running rewrites this file.
//
// To pin a value by hand: edit it, set `source = authored`, and every later run
// will read this file back and leave it exactly as it stands.

source       = generated

death_anim   = cow_update_death              // a0-rsmod  rsmod states it
attack_anim  = cow_update_attack             // a0-rsmod  rsmod states it
defend_anim  = cow_update_defend             // a0-rsmod  rsmod states it

attack_sound = cow_attack                    // s1-rsmod  synth 369
defend_sound = cow_hit                       // s1-rsmod  synth 371
death_sound  = cow_death                     // s1-rsmod  synth 370
```

### Why the ledger is not simply 16,292 `.npc` files

That was the obvious shape and it is wrong three times over.

1. **cachepack would silently drop 94% of them.** `cp_walk_find` fills the
   caller's array and stops — `matched < out_capacity` — and every caller passes
   `CP_PACK_MAX_SOURCES`, which is **1024**. 16,292 `.npc` files would pack 1,024
   and report success. Truncation with no error is the worst available failure.
2. **A block is not free.** An npc with no block is answered straight from the
   cache; the moment one exists, `npc_default.npc` overlays its own `attackrate`
   on top. So "this pipeline has no answer for this npc" — true of 10,055 of them
   — must *not* become a block. A ledger can record a non-answer; a config cannot.
3. **The ledger holds what the config cannot express.** Which layer decided, what
   it overruled, and, for sounds, the **name**. cachepack has no `synth` type
   (`cp_types.c`'s `g_types` lists twenty and sound effects are not among them),
   so a sound param in a `.npc` can only be a bare id. The name is the half that
   survives a cache revision, and this is where it lives.

### The contract

Edit a ledger file, set `source = authored`, and it is frozen forever: later runs
read it back and never overwrite it. There is no second place to register the
exception. Verified end-to-end — pin a value, regenerate, and it is still in the
ledger *and* in the compiled config.

One trap the ledger now warns about in the file itself. An npc that also has a
hand-written `.npc` block anywhere in `server/scripts` is skipped by the compiler
entirely, because an authored block always wins. Without a warning, pinning a
value in such a ledger file looks like it works — it survives every regeneration
— and never reaches the game. Those 199 files say `// NOT COMPILED` and name the
file to edit instead.

## 3. The animation layers

Highest confidence first. Each fills only what the ones above left empty, and
every row records which layer answered.

| layer | rule | slots filled |
|---|---|---|
| `a0-rsmod` | rsmod states it | 156 |
| `a0-lc` | LostCity states it | 851 |
| `a1` | on the npc's rig **and** shares a distinctive word with its name | 8,328 |
| `a2` | the rig offers exactly one candidate for the slot | 2,464 |
| `a3` | several candidates, no name to separate them — rank | 4,973 |
| `a4` | the rig names no action; classify by `forcedpriority` | 167 |
| `a5` | nothing; keep the human default and say why | 31,937 |

### a0 — and the rule this pipeline learned the hard way

**The rig gate applies to a0 too.** Being stated by another server is not the same
as being *playable here*: a sequence built on a framemap the npc's model does not
use drives bones the model does not have.

457 of LostCity's 1,303 rows fail that gate — **35%** — because Jagex re-rigged the
creatures. The cow is the clean case:

- LostCity says the cow dies by `cow_death`, which lives on framemap **282**.
- This cache's cow is on framemap **1338**, whose sequences are `cow_update_walk`,
  `cow_update_attack`, `cow_update_defend`, `cow_update_death`.

The old sequence still exists in the cache, so a *name* check passes and a *rig*
check does not — and the rig check is the one telling the truth. The right answer
was on the rig the whole time. rsmod fails the gate **0 times out of 156**.

Before this gate existed the highest-confidence layer was the one shipping
unplayable animations, which is exactly the failure mode the rig constraint was
introduced to prevent, arriving through the door marked "authored data".

### a0 — why rsmod's raw ids are usable at all

rsmod states seq **ids**, from revision 231, and this tree is 239. "Ids never
cross trees" says distrust them. So they were checked rather than trusted:

```
rsmod animation rows                         156
  resolving to a named seq in this cache     156
  sitting on that very npc's own rig         156     <- across 2,446 framemaps
```

156 of 156 landing on the correct rig out of 2,446 is not something a wrong id
space produces. Its 33 disagreements with LostCity are then era, not error — each
is a coherent attack/defend/death triple on consecutive ids:

| npc | 2004 | 239 |
|---|---|---|
| chicken | `chicken_*` 55–57 | `lore_chicken_*` 5387–5389 |
| rat | `rat_*` | `mouse_*` |
| giantspider1 | `giantspider_*` | `spider_update_*` |
| duck | `duck_death` | `duck_rework_death` |

**rsmod wins where the two differ.** This tree targets 239.

### a1 — rig ∧ name

The sequence must be on one of the npc's own framemaps *and* share a distinctive
word (4+ letters, not an action word) with the npc's gameval name. The name must
also account for ≥10% of the rig and ≥3 sequences — that is what separates a
creature word from a namespace word. `slayer` names 94 sequences and `gnome` 68,
so frequency cannot tell them apart; but on the rig each npc actually uses,
`gnome` is 40 of 98 while `slayer` is ~1% of framemap 0's 3,905.

### a2 — the rig is unambiguous

Drop the name gate where the rig alone answers: if an npc's framemaps offer
exactly one `*_death` sequence, that is how this creature dies whatever it is
called. Only on rigs of ≤200 sequences (`MEGA_RIG_SEQS`) — framemap 0 holds 3,905,
every human plus every emote and cutscene, and "the only `*_death` on this rig"
means nothing there.

The mega-rig restriction costs less than it looks. 6,960 npcs sit on such a rig
and they are overwhelmingly humans, for whom `npc_default.npc`'s human unarmed set
is *correct*.

### a3 — rank the candidates

The weakest layer, and flagged as such. The tie-break is the npc's own
**`readyanim` stem**, then the plainest name (`zuk_death` over
`zuk_death_hardmode` — a creature names its default variant with the bare word).

`readyanim` is the right signal because it is the one animation the *cache itself*
binds to this npc, so it names the family the creature's other animations belong
to. The goblin's is `slice_surface_goblin_squat_ready`, which is how you know the
modern goblin is the `slice_surface_goblin_*` family and not the
`champions_goblin_*` or `100_goblin_*` ones sharing its rig.

An ablation over the slots a3 owns settled this, and removed an input:

| ranking | vs rsmod (239) | vs LostCity (2004) |
|---|---|---|
| readyanim stem, then plainest | **21/36 58%** | **82/336 24%** |
| plainest name only | 10/36 27% | 71/336 21% |
| `npc_name_matches.csv` affinity score | 10/36 27% | 69/336 20% |
| longest shared prefix with readyanim | 21/36 58% | 82/336 24% |

The affinity score ranked no better than ignoring the npc entirely, so it and the
24 MB, 314k-row file it needed were dropped. The same tie-break was then added to
a1, where it moved a1 from 71% to 86% against on-rig LostCity truth at no cost.

### a4 — classify by `forcedpriority`

For rigs whose sequences name no action at all. `forcedpriority` is the engine's
interruption rule, which is why it carries meaning a naming convention would not:
a death animation is precisely the one that must play to the end.

The 2,556 sequences whose names *do* state an action are a free labelled set, and
`--validate` recomputes this confusion table on every run:

| `forcedpriority` | labelled | verdict | used as |
|---|---|---|---|
| 10 | 514 | 98% death | death |
| 11 | 18 | 100% death | death |
| 6 | 809 | 99% *not* death (83% attack) | attack |
| 7 | 84 | 98% not death (95% attack) | attack |
| 8 | 60 | 100% not death (95% attack) | attack |
| 9 | 51 | 50/50 | **unused** |

a4 only fires when the rig offers exactly one such sequence. It does **not** try
to split attack from defend by duration: labelled attack runs p25=31 / median=51 /
p75=69 cycles and defend p25=36 / median=48 / p75=63, distributions that sit on
top of each other. A signal that does not separate is not used.

## 4. The sound layers

| layer | rule | slots |
|---|---|---|
| `s0` | the chosen animation carries its sound in-band; nothing to write | 1,069 |
| `s1` | LostCity/rsmod state it, resolved through `pack/4_soundeffects.pack` | 1,511 |
| `s2` | seq-name → sound-name join — **measured and rejected** | 0 |
| `s3` | silence | 46,296 |

**s0 is the interesting one.** The sound is already in the cache, attached to the
frame it fires on, with a weight for choosing among alternatives — and the client
already plays it. Getting the animation right is the entire job.

**s2 was measured rather than assumed.** The rule "a sound named like the
sequence is that sequence's sound" is right when it fires: on the 1,411 npc rows
that state both an animation and its sound, the animation's own name is also a
sound name 448 times, and 341 of those are the sound the npc actually uses. But it
only *fires* on 31% of rows, so it cannot carry the 96% of npcs no source
describes. Rejected, and `--validate` reprints the measurement each run so the
rejection stays checkable.

**s3 is the honest answer, not a gap.** `default=-1`, and specifically not 0 —
sound effect 0 is a real clip, and a 0 default is what made all 1,083 weapons play
the same sound on every swing (`WEAPON_FX.md` §6.6).

The three npc params are new (`npc_combat.param`, `fields/npc.ini` opcodes
158–160, `mock230_servercodec.c`, `Mock230NpcDef`). `player_ranged.rs2` has wanted
`defend_sound` since it was ported and recorded its absence in a comment.

## 5. How the layers are graded

`--validate` re-runs a1–a4 with **a0 switched off**, on exactly the npcs a0 can
answer, and compares. Graded against each source **separately**, because the two
sources are two different games:

```
  layer   vs rsmod (revision 231)     vs LostCity (2004)
  a1              47/53    88%          323/548   58%
  a2              19/19   100%          115/159   72%
  a3              21/36    58%            82/336   24%
  a4                 (silent)              5/5   100%
```

Every layer scores far better against the modern source, and **the 2004 misses
are the reason**:

```
  a1  black_demon     defend_anim   2004 demon_block     -> demon_update_defend
  a1  black_unicorn   death_anim    2004 unicorn_death   -> unicorn_rework_death
  a2  bat             attack_anim   2004 bat_attack      -> bat_rework_attack
```

Those are Jagex reworks, and rsmod picks the same reworks independently
(`chicken` → `lore_chicken`). A cache-derived layer preferring the cache's newer
animation over a 2004 server's older one is the layer being *right*. Grading
against a single blended "truth" would have reported a1 at 57% and hidden this
entirely — which is what the first version of the harness did.

## 6. Coverage

```
npcs                                                    16,292
  with at least one animation of their own               6,237   (38%)

of the 3,973 npcs a player can attack:
  have at least one animation of their own               2,878   (72%)
  on the shared human rig, where the human set is right    832
  genuinely unanswered                                     263    (6.6%)
```

38% of *all* npcs sounds low and is the wrong denominator: most of the 16,292 are
scenery, shopkeepers and quest actors that never fight. Among npcs that can be
attacked, **93% are either answered or correctly answered by the human default**,
and 263 are left genuinely unknown.

Those 263 keep the human set and their ledger file says why. That is deliberate:
guessing a monster's animation from its family would reproduce exactly the failure
the player half of this problem suffered — a plausible wrong answer that nothing
reports.

## 6b. Playing them

Identifying a sound and playing it are two jobs; this is the second.

**Each sound sits with the animation it belongs to** — that is the whole placement
rule, and it decides engine-vs-content on its own rather than by preference:

| event | animation played by | so the sound goes |
|---|---|---|
| npc swings | content, `[ai_opplayer2,_]` | content, beside `npc_anim` |
| npc flinches | engine, `play_npc_seq(npc->block_seq)` | engine, `npc_sound_nearby` |
| npc dies | engine, `play_npc_seq(npc->death_seq)` | engine, `npc_sound_nearby` |

Two things came out of doing it.

**The npc melee attack animation was never played.** `npc->attack_seq` was
resolved at spawn, asserted by a selftest, and read by nothing — the port of
LostCity's `[proc,npc_default_attack]` kept its last line (`~npc_meleeattack`)
and dropped `npc_anim(npc_param(attack_anim), 0)`. `npc_combat_ranged.rs2:28`
was the only place in the tree that played an npc's attack animation, so every
melee npc in the game attacked without animating, and the 5,938 attack animations
this pipeline identifies had nowhere to arrive. Both lines are restored in
`combat.rs2`.

**The death sound cannot hang off `[ai_queue3]`.** That trigger is exclusive —
type, then category, then `_` — so the 136 drop-table binds suppress the default
rung, and a sound there would miss exactly the npcs players kill. It is engine-
side instead, which is also where the death animation already was.

**Broadcast, not per-player.** LostCity spells this as `~sound_within_distance`,
a proc that only ever runs for whoever triggered it; every one of its call sites
is inside a player's own script, so that is fine there and wrong here. An npc
flinches and dies inside the engine, and a bystander should hear it. The engine
emits to every active player within 12 tiles on the npc's level — LostCity's own
figure, `// osrs`.

**`loops` must be 1, not 0.** `~sound_within_distance` passes 0, and
`RS_Audio_QueueEffect` *refuses* `loops == 0` — matching the reference's
`Message.queueSoundEffect` requiring `var1 != 0`, because the count handed to the
mixer is `loops - 1`. A literal port of that proc would have been silent. Both
`[proc,sound_area]` and `[proc,sound_within_distance]` in
`general/scripts/misc/sound.rs2` still pass 0 and are unused; anything that
starts calling them will be silent until they are fixed.

The three params are new: `npc_combat.param` (`type=int`, `default=-1`),
`fields/npc.ini` opcodes 158–160 (`u4`, so -1 round-trips), `k_npc_fields` in
`mock230_servercodec.c`, and `Mock230NpcDef` / `Mock230Npc`. `type=synth` does
not exist — `cp_common.c`'s `k_param_types` has no entry for it and `'P'` is
already `param` — which is why the config carries a bare id and the ledger keeps
the name.

## 8. Traps

- **Trailing comments break `.npc` values.** A config line's value is the whole
  rest of the line, so `param=attack_anim,cow_death  // a2` names a sequence
  called `"cow_death  // a2"`. Provenance goes on its own line above the block;
  the ledger holds the detail.
- **An npc gaining an Attack option needs `attackrate`.** A block imposes
  `npc_default.npc`'s value, so the generator restates the cache's own where they
  differ — 834 npcs.
- **`pack/npc.server` must name every npc that gains a server field**, or the pack
  fails with "an entity cannot carry a field its own side does not receive". The
  generator merges into it in sorted position rather than rebuilding, because the
  file carries a mid-file comment block that a rebuild scatters.
- **Encoding is latin-1 throughout.** Display names come from a cachepack export
  of the cache's own bytes and are not all valid UTF-8. Reading and writing the
  same 8-bit encoding round-trips them; every character the generator itself
  contributes is ASCII so the two never collide.
- **The C side mirrors `fields/npc.ini`** and `test-servercodec` enforces it. A
  field added to the register and not to `k_npc_fields` fails the build, which is
  how the three sound opcodes were caught before they could silently not pack.

## 9. What would move the number

The 263 unanswered attackable npcs and the 96% of npcs with no sound both need
data that does not exist in the cache. The one route that scales is capture:
`SYNTH_SOUND` packets observed from a live server, keyed by the npc that emitted
them. That is almost certainly where rsmod's 53 sound rows came from, and it needs
a capture rather than a lookup — `NPC_SOUNDS_ANIMS.md` §Conclusion.
