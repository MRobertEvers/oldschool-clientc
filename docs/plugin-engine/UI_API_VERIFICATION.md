# Retained UI and settings audit: API obstacles and evidence

The settings/frame review of six plugins completed 114 attempts: 112 scenes with frames, all reviewed at 2×, and two preflight-only cache-compatibility blocks that never launched a client. Every run retains its binary SHA, compiled source commit, invocation, input hashes, original scorer output and exact observer attribution in the archived `/private/tmp/critic-fixes/full-visual-settings.json`, indexed by [the full visual matrix](full_visual_verification.json). The coordinating reviewer (`/root`) independently inspected eight F shared-roster representatives; the settings/frame reviewer inspected the other scenes. Final H passed 37 checks and six focused acceptance scenes. Detailed D/E/F/G evidence is explicitly carried forward only where source paths are unchanged; H rechecks native tab activation, complete-sidebar containment, provider release and Classic/Stone composition.

## Client settings and feature flags

The options setter could replace a list only when its count stayed constant. A provider choice changes the roster of choices, so the plugin previously had to invalidate and rebuild its page; that discarded the retained popup and scroll state. The host now resizes packed options atomically while keeping widget identity, and the Chrome dropdown remaps its open popup, hover and scroll to the new stable values. Both eras show the real popup surviving six-to-five choices. A real retained-input integration test also covers nonzero popup scroll; restoring the former setter fails the regression.

Interface scale had no reliable presentation evidence: the ordinary screenshot is the logical canvas, not the physical window presentation. A separate opt-in SDL presentation capture proves actual 100%/150% dimensions. Fixed mode retains its historical point-size base on Retina, while resizable mode respects drawable density. Scale changes avoid re-reading transient stale child geometry as a new persistent floor. Oversized hidden mounted children are excluded consistently by compact and full floor queries.

Generated settings rows also had duplicate interpretations of persisted values. The UI's `atoi` path disagreed with the host's Boolean spellings and expression parser. One authoritative host Boolean read now builds checkbox state. Save preflights every value with the same schema validator and only then writes original valid expressions; `1 << 4` and `0x20` retain their meaning, and an invalid row cannot partially save other rows. Reload first unclaims every schema index so removed keys remain preservable. Draw-distance's zero sentinel is reported using the effective descriptor value (25 tiles), without rewriting the stored sentinel.

## Gameframe layout

Watching a role's parent was insufficient when its member set changed while the parent survived. The provider now compares member identities when tree/binding publication occurs. The opt-in role-resolution fixture masks only chat-button membership while retaining real native parents, publishes through the ordinary binding path, and restores through that same path. At 2×, the normal and restored hover offers `Hide chat`; the missing-member state offers only native `Public chat: On`, proving the obsolete transparent controls were retired. This is a service-boundary stimulus, not a claim that the pinned cache naturally performs that exact remount.

Nonzero-origin layout needed a real producer. The existing widget API is sufficient: move the highest native rail ancestor sharing the rail's exact bounds, then perform an ordinary resize. Moving the rail child's already-zero local x was a valid no-op; that failed first stimulus is preserved. The corrected capture places the rail at x=0, width=42 and both viewport and chat at x=42, with complete controls.

Native selection and activation are different contracts. The legacy client always keeps a selected enabled tab open, confirmed by native and plugin repeated Stats presses. OSRS native activation can collapse a repeated tab; its `on_op` owns that policy. `cache.tab_select` intentionally selects deterministically and therefore cannot stand in for a pressed stone. The new additive `cache.tab_activate` keeps `sidetab_N` as the availability icon, then uses the declared tab-button enum and the current root’s authored component map to find its separate native operation stone. It dispatches the normal resolved native hook with primary operation index. Native availability remains authoritative; no revision switch or copied component table was added. The real native repeated-press control reaches -1→3→-1. The final H plugin sequence also reaches -1→3→-1 with exactly two widget-operation callbacks; fixed and legacy controls remain open as their native policies require.

The native sidebar API initially returned only the direct parent of numbered tab members. Its side-modal sibling and the outer native click barrier were excluded. The first repaired activation opened the sidebar, but the moved tab’s second press vanished: an ordered-input trace hit the owned tab, then the stale outer barrier cleared it. Sidebar resolution now returns the smallest common ancestor of all declared sidebar parts, including the primary side-modal. Semantic stamp changes invalidate its cache; tree generation and instance identity handle topology replacement. The real nested-topology regression preserves native panel operations and the unrelated root sibling, and the old resolver fails the moved-tab hit check. H verifies open/collapse, mobile inventory opening and release to native layout.

## Mobile gameframe

A safe rectangle states what the platform covers, but it does not prevent two plugin regions from overlapping each other. A 200px keyboard inset shortened the available height enough that the tall tab rail collided with map/orb reservations. The repaired layout uses a complete 5×3 grid with 40×40 touch targets, positioned outside the reserved map and chat regions. Both art families and both eras are covered by 332 geometry assertions and actual 2× inset frames. The old implementation fails 92 assertions.

Raising the keyboard and focusing native chat are distinct operations. OSRS real touch now produces visible typed text. Legacy real touch raised the keyboard but still lost typing focus: the owned default action requested focus, then App applied its outside-chat rule to that same unconsumed click. The pointer repair records owned-control consumption in both default dispatch paths. An integration regression uses the real focus request, real App focus policy and both actual ownership fragments; removing the ownership statements reproduces the failure. Final F live captures show `keys*` in the legacy chat line for both art families; the relocated keyboard button also turns input off correctly.

Retained decoration ordering requires the actual sibling-parent contract. Chat paper and filter backing must be siblings of the whole native subtree they anchor behind; a valid-looking anchor request to a descendant is refused. Earlier mobile repairs added an explicit decorative-background role, placed owned pieces under the correct parent with converted local coordinates, and checked each anchor result. Captions remain native and visible. Housing assets with malformed opaque windows are refused with an explanatory fallback so the native compass/world remain usable.

Two providers can coexist while asynchronous assets prepare, even though only one frame is committed. Real Classic→Stone→Classic settings transitions demonstrate that state on both eras. Peak residency was 237/384 image slots on OSRS and 231/384 on legacy; the outgoing provider remains available until publication, then releases. Early legacy picks that occurred before initial Classic readiness are preserved as unsuccessful stimuli. Supplemental scorer expectations name the explicit final Stone frame; original initial-Classic failures are not overwritten.

## Minimap orbs and loot tracker

A visible parent does not establish native action readiness. The actual OSRS run target can be hidden while its parent remains visible and its alternate OFF alias is absent. The blocked fixture shows no third native invocation, no Toggle Run hover, and the owned control disarmed; its matched visible control toggles normally. Lua previously discarded the native refusal reason, making unavailable, hidden and stale cases indistinguishable to the author. Both query stages now return nil plus the mapped native reason; the live blocked case reports `native_blocked`.

Loot custom-region hit testing previously used the last painted width, but layout can change before another paint. The presenter now supplies additive region dimensions on action events. A real retained custom activation is dispatched after layout and before the first plugin draw, repeated after resize, with a stale-presenter control. The tracker uses those dimensions for its semantic hit boxes. Live first/next-page views show progression beyond the old six-entry ceiling; only entries actually visible in each viewport are claimed. Both eras also show empty and real populated panels, with actual live loot counts and values.

The full report distinguishes production failures, unsupported native behavior, deliberately injected service-boundary states, unsuccessful probes and scorer expectation substitutions. A passing screenshot process alone is never treated as visual or behavioral proof.

The native-release control retains one visible baseline limit: native root164’s open inventory at minimum height overlaps part of its lower special-orb disc. The original strict pixel failure remains recorded. All 98 authored native frame geometry/paint/input fields match the prior native control, the provider stops, and no owned frame widget remains; no repair of that native overlap is claimed.
