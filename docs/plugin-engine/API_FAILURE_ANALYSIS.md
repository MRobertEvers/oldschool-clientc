# Plugin engine: visual failures and API causes

The full visual review is in progress. Its complete roster is [full_visual_verification.json](full_visual_verification.json): 19 shipped feature plugins, both supported revisions, the Lua host, and the public API examples. A test pass, a running-plugin log, or a generic pixel score is not a completed visual review. Each final record must identify its candidate, actual stimulus, opposite control, original pixels, inspection at 2x, and remaining limits.

The original [repair register](REPAIR_VERIFICATION_f7526e5b0.md) preserves all 80 audit findings and their original evidence. New findings from this review supplement it. The examples below distinguish an implementation error from a limitation or contradiction in the engine contract.

| Visible failure | What made correct implementation difficult | Repair and evidence |
| --- | --- | --- |
| A crowded NPC menu loses plugin actions for later targets; a larger menu extends below the canvas. | Native menus hold 400 entries, but the plugin snapshot stopped at 16 and action routing at 24. Consumers received a plausible partial list without a completeness signal. The presenter then assumed every retained row fit on screen. | Snapshot and route capacity now match native capacity. Menu scrolling preserves original action indices across clipping, wheel and touch navigation. A live stack of ten Banker NPCs exposed the clipped menu; the smaller five-NPC case separates snapshot completeness from scrolling. Final visual checks remain pending. |
| Native ground-item timers and edit graphics remain invisible despite enabled settings and live despawn metadata. | Runtime overlay creation understood primary and secondary widget selection, but compiler/decompiler metadata declared that selection unsupported. The pristine native row contains creation operands `0,1,0,0,1`; the rebuilt cache contained `0,0,0,0,0`. Timer text consequently targeted a graphic, while secondary graphics had no selected widget. The ordinary source still looked plausible. | The shared command metadata now preserves the dot form. A compiler → decompiler → compiler regression preserves both targets. The existing fingerprint-checked cache transformation normalizes only the exact known damaged input into the independently verified native bytes. No host-side target guess is used. |
| Filtering a ground-item caption can leave its native auxiliary controls behind. | The caption hook names one text widget, while the native row stores timers and controls as siblings. Hiding that widget has no authority over its siblings, and the original callback contract did not define whole-row suppression. | An empty callback caption now suppresses construction of the row's native auxiliary widgets. This contract is explicit in the hook specification, and the transformation preserves native branches for nonempty captions. Final timer/edit/reveal controls must prove the visible result. |
| Native NPC indicator scripts repeatedly fail immediately after creating an overlay. | Opcode 203's VM metadata required two integers and its host implementation searched for a child. The native bytecode supplies one overlay handle and selects the empty root before adding listeners and children. Unit tests using the incorrect signature could not prove compatibility with the real script. | The arity and root-selection contract now match the native call. Tests execute create → store/load handle → find → root listener → child text, including both target slots and missing-handle controls. Live replay must show the former script 6693 → 6695 failure disappears. |
| A saved dropdown closes or loses position when its option count changes. | The retained options operation treated same-length replacement as an update but changed-length replacement as invalid. Plugins had to rebuild a retained control to express a normal catalogue change, destroying interaction state. | Option slices resize atomically while the widget's open state and scroll position survive. Tests retain an open menu across shorter catalogues and preserve the previously visible option. |
| A loot-tracker click after layout, before paint, uses the wrong column width. | Input callbacks received coordinates without the current custom-region dimensions. Plugins therefore inferred hit geometry from the most recent draw, although layout and input can occur before that draw. | Draw and input share current region sizing, and action events include region width and height. The presenter/host integration test dispatches real retained actions before paint and after resize. |
| Frame decoration causes idle redraws and obscures where frame time goes. | Successful retained setters did not distinguish a no-op from an effective change. Repeating a winning value advanced ownership stamps, dirtied nodes and requested redraw. Callback timing and mutation attempts were not separately observable. | Winning equal writes are idempotent; later-owner precedence and release remain intact. Opt-in telemetry separates requests, effective changes, redraws, callback self time, logic iterations and actual presentations. [Measurement limits](../PLUGIN_TELEMETRY.md) prevent those counters being mistaken for a complete profiler. |
| FPS can reflect loop iterations or diagnostic renders rather than visible frames. | The counter's production point was a software rendering function, which omitted GPU presentation and included offscreen capture work. Changing the ordinary frame cap also slowed logic, so it could not test a 15-draw/50-loop case. | Counting now occurs at completed presentation, and an independent diagnostic draw gate preserves logic pacing. Final controlled captures must verify the displayed value against measured presentations. |
| A late item definition leaves a loot beam absent. | A ground snapshot with cost zero cannot distinguish a pending definition from a resident item worth zero. There is no definition-ready notification. A finite retry window therefore encoded an unsupported assumption about delivery time. | Loot Beams uses `game.item_info` readiness, polls only pending IDs every 25 ticks, and stops for resident zero-cost items and departed stacks. A response withheld beyond the former retry window is explicitly an API-response fixture, not evidence of simulated network latency. |
| Some shipped loot-beam colours cannot be reached. | Desktop and mobile preferences gave High and Insane the same threshold, while the inherited Medium threshold also matched them. Individual fields were valid; the configuration expressed an unusable tier ordering. This is a shipped configuration error, with no cross-field preview to expose it. | Shipped thresholds are distinct. The harness now accepts a real preference file without replacing it, so visual tier checks can test shipped values. |
| A long automatic screenshot name fails silently while a short subject saves. | The host bounded the complete filename; the script bounded only the subject slug. The API returned a generic refusal, and the success message used a long absolute path that clipped away the filename. The old collect command did not emit the native event, hiding the issue from captures. | Filename budgeting covers all suffixes and failure is reported. A private server script emits real long and short collection-log messages. The original build rejects the long name and saves the short control; the repair saves both. Actual saved images and final-candidate notices remain part of the visual gate. |

Unavailable data and unsupported features need separate treatment. A skill query can be absent because the server has not stated that skill yet; it is not an end-of-table marker. A touch-sized canvas does not prove finger input, and the desktop dummy backend cannot demonstrate a physical software keyboard. A native CS1 sidebar that is always open does not become collapsible merely because another adapter supports collapse. The final per-plugin records must state these boundaries and demonstrate the supported interaction instead of treating an unreached condition as a pass.

The verification fixtures preserve these distinctions: touch replay passes through the shared gesture translator and command bus; stat delay holds actual UPDATE_STAT payloads while other packets progress; role-membership and item-definition delays are explicitly service-boundary observations; long screenshot events travel through the private server's normal message packet and the client's native recognizer. The original audit worktree, cache and captures remain unchanged.
