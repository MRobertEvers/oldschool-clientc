# Tombs of Amascut — downloaded sources

Everything the plan and the encounter log cite, pulled down on **18 August 2026**
so that a later edit upstream cannot silently move the acceptance target. Each
wiki page is stored as raw wikitext and pinned to the revision listed below; the
`?oldid=` link renders exactly the text in `sources/`.

Nothing in `sources/` is authored by this project except the cache extracts,
which are mechanical dumps of `OSRS-Content/osrs239-content/`. Treat all of it as
evidence, not as specification: where two sources disagree this folder's readers
say so and pick one, and where no source settles a number the plan raises an
`[Mn]` task instead of inventing one.

## 3. Reference implementation — RSPS-NEAR-REALITY (not authoritative)

`~/Documents/git_repos/RSPS-NEAR-REALITY`, read but **not** copied. Two halves:

### `near-reality-server-main` — Zenyte-derived ToA content, 130 files, ~17.9 kLOC

`core-restricted/.../content/tombsofamascut/`. The most useful files, and what
each one is good for:

* `raid/EncounterType.java` — the **eleven rooms** with their 8-tile chunk
  origins, spawn tiles, challenge-area rectangles and the name of the music track
  each one plays. This is the single best geometry source in the folder and it
  cross-checks exactly against the cache's twelve map squares (§ASSET_INDEX §1).
* `npc/TOANPC.java` — the **scaling model**, written out: `raidFactor`,
  `levelFactor`, `damageFactor`, `teamSizeFactor`. See the deviation note below.
* `InvocationType.java` — confirms the invocations are read from cache structs
  with params 1159/1161/1162, which is how this project should read them too.
* `npc/Akkha.java`, `npc/Kephri.java`, `npc/Zebak.java`, `npc/Baba.java`,
  `npc/FlyingWardenNPC.java`, `npc/MovingWardenNPC.java`, `npc/WardensObelisk.java`
  — animation, projectile, spotanim and **sound-effect ids per attack**, which the
  wiki never states.
* `encounter/*.java` — room lifecycle: entry, challenge start, wipe, completion.
* `lobby/*.java`, `raid/TOARaidParty.java`, `raid/TOARewardInterface.java` — party
  formation, the invocation board, the scoreboard and the reward chest flow.

**Known deviation, do not copy:** `TOANPC.setMaxHealth()` scales hitpoints by
`1 + (teamSize - 1) * 0.9` for every extra member. The wiki states 90% for the
2nd and 3rd member and **60% for the 4th and beyond**. The reference is wrong
above a trio; this project follows the wiki.

**Second deviation:** its unique-chance formula (`10500 - 20 * min(RL, 400)`, with
a 1/3 taper past 400 and a 550 ceiling) is an older shape than the wiki's current
three-branch scaled raid level. Follow the wiki.

### `near-reality-client-main` — the duckblade **Tombs of Amascut** RuneLite plugin

`runelite-client/src/main/java/com/duckblade/osrs/toa/`, 65 files. A client-side
observer, so every constant in it is something the real server does:

* `util/RaidRoom.java` — the eleven rooms **by region id**, which is the same
  geometry as `EncounterType` arrived at independently.
* `util/RaidMode.java` — Entry 0–149 / Normal 150–299 / Expert 300+.
* `util/Invocation.java` — the 44 invocations with their raid-level values.
* `features/pointstracker/PointsTracker.java` — the **point multipliers per npc**,
  the 5,000 start, the 20,000 room cap, the 64,000 total cap, the MVP bonus of
  `300 * teamSize`, and the death penalty of `max(20%, 1000)`.
* `features/het/beamtimer/BeamTimerTracker.java` — Het's caster statue fires every
  **9 ticks**; graphics-object ids 2114 / 2064 / 2120.
* `features/het/solver/HetSolver.java` — the mirror/beam puzzle as a solvable grid.
* `features/scabaras/overlay/*.java` — one solver per Scabaras puzzle: sequence,
  obelisk, light-out, addition, matching. These encode the puzzle rules exactly.
* `features/apmeken/Baboon.java` + `ApmekenWavePanel.java` — the seven baboon
  types and the eight-wave table.

## 4. How to re-fetch

Wiki pages, one request per second with a contact User-Agent, `action=parse` per
`oldid` so the stored text is byte-identical to what the `?oldid=` link renders:

```
python3 tools/toa_fetch_wiki.py docs/minigames/tombs_of_amascut/sources <<'EOT'
Tombs of Amascut
Tombs of Amascut/Strategies
...
EOT
```

The Combat Achievement table is the same script in a different mode — it finds
its own titles, so a task added upstream appears on the next run rather than
being silently missed:

```
python3 tools/toa_fetch_wiki.py docs/minigames/tombs_of_amascut/sources \
    --combat-achievements
```

Cache extracts, including the invocation table:

```
python3 tools/toa_cache_dump.py OSRS-Content/osrs239-content \
    docs/minigames/tombs_of_amascut/sources
```

Both were re-run against the committed files after being written, and both
reproduce them byte for byte.
