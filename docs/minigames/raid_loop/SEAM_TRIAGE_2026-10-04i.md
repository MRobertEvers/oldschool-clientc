The owner, 2026-10-04: "I don't want to introduce nondeterminism. The server and clients should be able to run in lockstep." Seam17's party link (src/torirsserver/torirs_server_embed.c, src/platform/net_transport_embed.c; DRIVER_NOTES.md "Three raiders in one run", "Lock step: READY, then TICK") already holds the SERVER in lockstep: the leader runs a world tick only after every member's READY, feeds each member's buffered input into its session at that boundary in seat order ahead of the tick (`party_barrier` -> `party_take_frames`), and hands each member its output as a burst followed by TICK; a member blocks at its boundary until TICK. Solo runs are deterministic today (TORIRS_MAX_FRAMES frame-locks the client, TORIRS_EMBED_CLOCK_MS the server). This pass makes a party run equally deterministic: byte-identical tick logs AND member ledgers across repeated runs, or the run fails loudly.
