THE DESIGN. A VIEW (`struct App_WorldView`) holds what the script and the watcher must not share: the camera pose (orbit, world_camera, world_camera_pos, zoom, cam_hold, projection_scale), the camera input latches (cam_key_*, cam_mmb_*, camera_unlocked), the pointer over the world (world_mouse_x/y and its valid flag), the pick results (world_pickset, world_hover_tile_*), and the right-click menu (`interact.minimenu`: one per view). SHARED, not in the view: the world, the character, the UI tree and layout, the viewport rectangle and emit desc, and the game's scripted camera state (cam_script), which applies to EVERY attached view. Two ROLES: AutomationRunner (what a script's verbs read and write) and PlayerClient (what is presented and what the physical mouse and keys control). `app->views[0]` always exists and is today's fields; `app->views[1]` exists only while a script runs in a windowed client. Headless: views[0] = AutomationRunner, nothing presented, the same path as today. Window, no script: views[0] = PlayerClient. Window, script running: views[0] = AutomationRunner, views[1] = PlayerClient, created as a COPY of views[0] when the run starts (no jump) and copied back into views[0] and freed when it ends (no jump). `app->frame_view` names the view of the frame being built and is set at stage boundaries; readers of `app->world_camera` read `app->frame_view->...`; kernels are untouched (they already take a camera pointer). A WATCHED FRAME: input (physical -> PlayerClient view; driver events -> the runner's pointer), logic, the follow step for each attached view, THEN, only if a verb asked for a pick or a shot, an OFFSCREEN frame built and executed through the AutomationRunner view on the software lane (the catch-up / capture path with the view as a parameter: it fills the runner's pickset and/or the screenshot), THEN the presented frame through the PlayerClient view on the active renderer, picked at the watcher's pointer. The offscreen frame runs FIRST so every piece of shared painter state is left as the presented frame wrote it. THE OFFSCREEN FRAME'S CONTRACT: it does not run ToriRS_FrameEnd or drain load events; it does not advance animation or the no-bind-pose accumulation; it has its own painter buffer; it consumes no rand() (the shake is rolled once per frame and shared); it does not count against the paint-limit step; its pick is armed at the runner's pointer. INPUT: each input event carries its source (physical or runner) and its own position; a gesture is never interleaved with the other source's (while the runner is between a press and its release, or between a right press and the menu row it will press, physical presses wait); hover follows whichever pointer moved last; keyboard focus decides who types. THE INTERACT SWITCH (owner decision 1): a button in the Scripts panel, OFF when a script starts; OFF = the physical mouse and keys are spectator controls (orbit, zoom, hover-inspect the world through the PlayerClient view, the Scripts panel) and game clicks and typing do nothing; ON = they act on the game normally through the PlayerClient view (its pointer, pickset and menu); the state is ALWAYS indicated on the game frame (a badge: "Runner has control" / a warning-coloured "You can interact"), not only in the panel; every watcher action while ON writes a ledger row (the tick and what was done); the switch does not pause the script. SCRIPTED CAMERA (decision 2): CAM_* packets, cutscenes, CAM_FORCEANGLE and shake take every attached view. MENUS (decision 3): the menu that does not belong to the presented view is drawn in a different colour and takes no physical clicks. SCREENSHOTS: a script's shot is the runner's view through the offscreen frame (world, overlays projected through the runner's camera, UI); remove the 63ea41d39 guard in `_shot_plan` once that holds. THE DRIVER attaches: the run wrapper calls `api_drive.view_attach("AutomationRunner")` at start and `view_detach()` at finish or stop; no test file changes; headless creates nothing. NOT IN THIS PASS: a picture-in-picture of the runner's view, a raster-free pick pass, a native second 3D pass on the GPU lanes.
