# Inferno code constants: one row per stated constant

Written 2026-10-03 by the waves loop's plugin / simulator / reference-server corpus worker (`corpus.code`). Every
row points at a line of a **pinned copy** under `docs/minigames/inferno/sources/` (files copied byte for byte with
their licence header, so the line numbers are the upstream file's). The ledger with the fetch dates and commits is
[`LEDGER_code.md`](LEDGER_code.md); each source directory carries a `README.md` naming repo, commit, files, licence
and what the source credits as its own sources.

## How to read the "other pinned sources" column

* **AGREE** and **DISAGREE** are read from the lines cited; a disagreement is listed as open, never averaged.
* Two code sources agreeing only makes a row **grade C later** when they are *independent*. The pinned code falls into
  four lineages, and a row that two sources of the same lineage share is one source, not two:
  * **A, OpenOSRS lineage** (RuneLite client plugin): `openosrs_inferno/` (2020, tag `OSRS`/`OOS`) and `kotori_inferno/`
    (2026, `KOT`). Kotori is a maintained descendant of the OpenOSRS plugin (same class names, same constants, the
    same `// TODO: Could be 10 or 11. Test!` line 511-513). It **observes the live client**: animation ids, ticks after
    an animation, safespot geometry. It states no hitpoints.
  * **B, InfernoTrainer lineage** (a simulator): `infernotrainer/` (`IT`, GPL-3.0) on the engine `osrs_sdk/` (`SDK`);
    `autozuk/` (`AZ`, MIT) is built on it (identical dig constants -38/-50, 10% revive, 6/6 dig, spawn list) and adds
    its own "calibrated" monster projectile tables. `triple_jad_sim/` (`TJS`) is a **compilation** of the wiki, the
    OpenOSRS plugin, InfernoStats, inferno-scouter, runemarkers and the trainer: it is a map to claims for the wiki
    worker, never a source for a row.
  * **C, client observers of the live game**: `inferno_scouter/` (`SCT`), `inferno_2d_map/` (`M2D`),
    `infernostats/` (`IST`): ids, region, grid, spawn tiles read off the first tick. They state few mechanics.
  * **D, the set timers**: `settimer/` (`SET`), `inferno_timer_maxswa/` (`TIM`), kotori's spawn-timer infobox: the
    210 s / 105 s constants. SetTimer says it is "inspired by bistools timers": one community origin.
* The sim sources say what they are built from: the trainer's sidebar links the wiki ("Mob Explanations"), its README
  names the Inferno Stats plugin for replays; the SDK says its line-of-sight code is "copy pasta'd between basically
  every trainer". **A simulator is built from observed data and is not Jagex's code**: none of its constants is a
  grade-A statement. The reference servers (Kronos, LostCity) are not in this table at all: see section 3 of the
  ledger.
* Frames: "trainer frame" = InfernoTrainer local coordinates (region x - 6, 60 - region y). "Region" = the 64x64
  region 9043 coordinates (world = region + (2240, 5312), **derived** from the region id, not stated by a plugin).
  The conversions were verified by script on 2026-10-03: the nine spawn tiles and three pillars map one to one between
  the scouter, the trainer and AUTOZUK.
* `OPEN` = needs the cache, the wiki, Blert or our tick log; the row says which.
