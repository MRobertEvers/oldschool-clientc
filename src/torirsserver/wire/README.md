# torirsserver/wire

The server's wire layer: which bytes it writes to, and reads from, each client
revision. The protocol itself is `3rd/rsprot`'s: its prot tables (opcodes,
sizes, zone sub-packet ordinals), its packet codecs, and its PLAYER_INFO /
NPC_INFO writers. What lives here is the server's side of that: which canonical
packet (`net/rev/pktnames.h`) each prot carries, the writer set a revision
uses, and turning decoded client packets into the bodies the world reads.

```
core/                        shared by every OSRS revision the server speaks (239..242)
  wire_prot.h                  a revision's prot lookups: RSProt's table plus the
                               server's canonical-name map
  wire_in.c                    the canonical client->server bodies the world handlers read,
                               one writer per body, plus the bodies that never changed
  wire_if_inbound.c            IF_BUTTONX / IF_SUBOP / IF_SCRIPT_TRIGGER / dialog decoders
  wire_runclientscript.c       RUNCLIENTSCRIPT: the golden client's limits, then
                               rsprot's packet_runclientscript_v1_out
osrs230/                     the hybrid table this repo's own client speaks
  osrs230_wire.c               opcodes only; payloads are torirs_server_encode.c's
  packetin.h packetout.h       the prot tables (hand-kept: not RSProt's 230 layout)
osrs239/ osrs241/ osrs242/   one OSRS revision each
  osrs<N>_prots.h              GENERATED by tools/rsprot_gen_rev.py: the canonical
                               name of each prot, by RSProt's RSPROT_OSRS<N>_* constant
  osrs<N>_wire.c               its adapter: opcode lookups and the whole writer set
  osrs<N>_inbound.c            client->server: decode with rsprot's osrs<N> codecs,
                               hand the fields to core/wire_in.c
```

In rsprot, beside the readers of the same streams:

```
3rd/rsprot/streams/
  player_info_write.h/.c       PLAYER_INFO's GPI bit sections and per-observer state
  player_info_write_osrs<N>.c  revision N's extended-info tail: player_info_osrs<N>_write
  face_write.h                 the actor facing block
  npc_info_write.h/.c          NPC_INFO's empty packet and its sentinel rule
3rd/rsprot/gen/osrs<N>_prot.h  RSPROT_OSRS<N>_SERVER_/_CLIENT_<prot> opcodes,
                               RSPROT_OSRS<N>_ZONE_<prot> ordinals
```

`../torirs_server_wire.h` is the seam: a `ToriRSServerWire` per revision
(`ToriRSServer_Wire230()` .. `ToriRSServer_Wire242()`, or `ToriRSServer_WireByName`),
whose `translate_in` and `payload` slots point into these files. Nothing above
the seam asks which revision it is.

## Adding a revision

1. `3rd/rsprot/spec/tables/osrs<N>.ini`, then `3rd/rsprot/tools/rsprot_gen.py`.
2. `tools/rsprot_gen_rev.py <N> --out src/torirsserver/wire/osrs<N>`.
3. `osrs<N>_inbound.c`: copy the nearest revision's and change the codec
   suffixes (`packet_oploc1_v2_osrs<N>_in`); every rsprot packet header names
   its per-revision entry point. A field that moved is rsprot's concern, not
   this file's; a packet that changed MEANING gets a new writer in `core/wire_in.c`.
4. `3rd/rsprot/streams/player_info_write_osrs<N>.c`: the tail's flag bits, block
   order and transforms, next to the revision's reader.
5. `osrs<N>_wire.c`: the writer set, then a `ToriRSServer_Wire<N>()` and a
   line in `ToriRSServer_WireByName`.
6. Add the files to `TORIRSSERVER_WIRE_SRCS` in `src/makefile`.

## Tests

test-osrs242-player-info test-wire-if-inbound test-wire-runclientscript
test-osrs239-interface-setters test-osrs239-varp test-loc-ops-wire`
