# Every plugin on the CS1 lane, LOGGED IN against LostCity_Server.
#
# The drives are NOT the cs1 (offline) ones. `dropobj`, `setlevel` and `xp` are
# the EMBEDDED server's cheats; only `lootkill` is handled client side
# (app_net.c's app_client_cheat), so everything else here is a LostCity
# debugproc with a `~` prefix. @see lostcity.sh.
#
# Every line opens the same way and it is not boilerplate:
#   click (259,285)  -- accept the character designer; a new account is parked
#                       on it and nothing else happens until it is dismissed.
#   ~skiptutorial    -- set %tutorial past the end AND re-run the login block's
#                       tab mount. Without it the sidebar has NO tabs at all:
#                       no inventory to hover, no skills tab, no prayer book.
#   ~varrock         -- somewhere with scenery, npcs and other players in it.
#
# No account is named. shot.sh derives a base37-safe one per shot, so every
# line is a different player and none of them waits out another's session
# (LostCity answers login reply 5 for about a minute after a client leaves).
#
# ---- AND THAT IS WHY A ROW'S FIRST EVER RUN HAS NO CHAT PANE ----
#
# A derived-per-shot account means a row's FIRST run is a brand new player, and
# a brand new player's first login is the one login that runs the tutorial:
# `login.rs2` calls `@start_tutorial` only while `%tutorial < ^tutorial_complete`
# AND the player is standing on tutorial island, both of which are true exactly
# once. `~tutorial_step_getting_started` then puts the "Getting started"
# parchment in the chat region with `tut_open`, and NOTHING IN THIS DRIVE TAKES
# IT DOWN: the box lives in the engine's TUT modal slot, `~skiptutorial` closes
# interfaces with `if_close`, and `Player.closeModal` clears modalMain,
# modalChat and modalSide and never modalTutorial. Only `tut_close` empties that
# slot, and the cheat does not call it.
#
# While it is there the chat builtin does not draw AT ALL -- not the log, not
# the input line (`RS_UISlots_ChatRegionIface`) -- so every plugin that speaks
# in the chat photographs as a plugin that said nothing.
#
# This is not a race and it is not luck. Measured across the forty-seven
# captures of 2026-09-14 taken on this lane's own 2004 frame: THIRTY-SEVEN have a
# covered pane and ten do not, and the ten are exactly the shots whose account
# file predates the sweep. `control-live` is one of the thirty-seven, which is
# why a control-vs-shot diff could not see it either.
#
#   * The client now states it: `CHAT_REGION iface=.. log_visible=..` is written
#     beside the BMP in every capture, and `live_check.py` fails on it.
#   * `lc_prime.sh` is the supported way to warm an account. Running the same
#     row a second time under the same name does it too, and is what the
#     before/after pair for this defect used as its only variable.
