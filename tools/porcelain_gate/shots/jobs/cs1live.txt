# A TAG IS AN NPC ID, AND AN NPC ID IS A FACT ABOUT THE LANE'S CONTENT.
#
# This line used to carry the cs2 job's tag list -- 5037,6708,2880,2899,3106,
# 3108, which are osrs239 ids. LostCity's npcs are three-digit ids from its own
# npc.pack, so not one of those six named anything the scene contained, the
# plugin drew nothing, and the shot came back a picture of Varrock square with
# no highlight in it. Nothing in the run said so: the config write reported
# applied=1 (it IS a valid tag list -- tagging a species that is not in front
# of you is normal), and a driven run with TORIRS_TRACE_PLUGIN_WORLD=1 shows
# zero PLUGIN_HULL lines for all 2200 frames. A dead plugin and a working one
# photograph identically here, which is the one thing a shot must never do.
#
# So the ids are chosen from the spawns this drive actually walks into.
# ~varrock lands on 0_50_53_13_31, and content/maps/m50_53.jm2's NPC block is
# the authority for what stands near it:
#
#   547 baraek  (18,43)  the fur trader
#   781 shilop  (21,42)  \  the two children at his stall
#   783 wilough (21,43)  /
#
# All three spawn NORTH of the teleport tile -- the direction the camera looks
# over the player's shoulder -- and all three declare wanderrange=2, so they
# cannot leave the forward view during the run. That is why they are here and
# 639 (romeo, two tiles away and the obvious first choice) is not: romeo
# declares no wanderrange at all, takes the engine default, and is somewhere
# else by frame 2200 -- tagged, correct, and invisible, which would leave this
# capture as ambiguous as the one it replaces.
#
# The OFFLINE cs1 lane cannot photograph this plugin at all, whatever the tags:
# it never logs in, so the npc pool is empty and app_plugin_npc_next answers
# -1 on the first call. Measured: a cs1 run tagging 547,781,783,639,153,1,3
# logs zero PLUGIN_NPC lines. Only this lane has npcs to highlight.

# ~maxme is here and nowhere else: it is what puts a real number on an xp orb,
# and it also floods the chat with level-up dialogues, so no shot that wants a
# readable chat pane can afford it.
#
# It fires at 2150 and not at 1000, and that is the whole shot. An orb is a
# THING THAT EXPIRES -- `orb_duration` is 10s, the "+N" that climbs into it
# lasts 1.2s -- and 1000 to 2200 is 1200 frames, about 22 seconds at the 20ms
# pacer. The old line raised every skill at frame 1000 and photographed frame
# 2200, twice the orb's whole life later, so the capture held not one plugin
# pixel: five globes were planned, logged at x=137..337 y=4, and every one of
# them had gone by the time the BMP was written. That reads as "the plugin is
# dead on CS1" and it is the recipe, not the plugin. 2150 leaves 50 frames --
# one second -- which is inside both clocks, so the shot carries the globes AND
# the labels still in the air under them. Anything earlier than ~2140 loses the
# labels; anything earlier than ~1700 loses the globes too.
